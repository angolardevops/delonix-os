# Design decisions

The decisions that are expensive to reverse, with the reasoning behind them.
Anyone who disagrees six months from now should be able to see what was known
today.

> 🇦🇴 [Esta página em português de Angola](../pt-AO/decisoes.md)

## 1. Base: Manjaro, not plain Arch or Debian

Manjaro gives three things for free that would otherwise cost months: `mhwd`
(driver detection and installation, NVIDIA included), multiple kernels side by
side, and a ~2-week delay behind Arch that catches the worst regressions. You
lose purity; you gain a distro that boots on real hardware.

Plain Arch would mean maintaining that layer ourselves. Debian/Ubuntu would give
stability but old packages — unacceptable for tools moving at the speed of
`kubectl` and `opentofu`.

## 2. Minimal Plasma, not the `plasma` group

We install `plasma-desktop` plus chosen pieces, never the meta-packages. The
`plasma` group drags in PIM, Discover, Bigscreen and `baloo`. The rule: every
desktop package on the list must have a named user — if nobody uses it in a
normal working week, it goes.

## 3. Containers: rootless and daemonless; Docker's daemon stays out

This is not ideology — it is what allows delegating cgroups to the user session
and containing the blast radius of a compromised container. `podman`, `buildah`
and `skopeo` are the fallback for third-party OCI images.

The `docker` CLI **is** installed (with `compose` and `buildx`), because everyone
already has scripts written against it. `DOCKER_HOST` points at the rootless
Podman socket, pre-enabled in `/etc/skel`, so it works without root and without a
daemon. Whoever really wants `dockerd`: `sudo systemctl enable --now docker` —
recorded as an administrator's decision, not as an omission by the distro.

## 4. tmux as the default console

On a machine that spends the day with remote sessions and long processes, losing
the terminal is losing work. `.zshrc` runs `exec tmux new-session -A -s delonix`
in any interactive shell — `-A` means "attach or create", so it never duplicates
sessions.

Cost: people who do not know tmux find the prefix strange. Hence two documented
escapes (`DELONIX_NO_TMUX=1` and `~/.config/delonix/no-tmux`) and a `.tmux.conf`
that uses `C-a`, which most fingers already know.

## 5. Branding generated by code, not binaries in the repository

`branding/gen-assets.py` draws everything with Pillow. Changing the palette means
changing three constants; a branding PR is readable as a diff. It also keeps 4K
PNGs out of git history. Cost: no designer freedom without touching code —
acceptable while the mark is geometric.

## 6. Animated splash from frames, not drawn at runtime

Plymouth runs before there is an accelerated GPU, with a very limited
interpreter. Drawing the rings each frame would be slow and fragile; 24
pre-rendered PNGs swapped at ~25 fps cost almost nothing. The frame count is
**fixed in the script** — discovering it at runtime would mean calling `Image()`
on files that may not exist, and that aborts the whole splash. `verify-profile.sh`
guarantees the file count and the number in the script never diverge.

In KSplash (Plasma and GPU already up) the same motion is done in QML, which
stays sharp at any DPI.

## 7. Privileged ports stay closed

Lowering `ip_unprivileged_port_start` to 80 is convenient and is what most
rootless guides suggest. It also lets any user process impersonate a system
service. It stays explicit opt-in (`delonix-toolbox unprivileged-ports on`), with
the trade-off written in the file.

## 8. Packages, not overlay — and the boundary between them

A file copied into the image is written once and never changes: whoever installed
v1.0 would keep that theme and that tuning **forever**. So everything that needs
to evolve ships as a pacman package in the `[delonix]` repository:

| Package | Contains | Why it must be a package |
|---|---|---|
| `delonix-os-branding` | themes, wallpapers | a badly drawn logo gets fixed for everyone |
| `delonix-os-settings` | sysctl, cgroups, KVM, initramfs, tuned | a limit that is enough today will not be tomorrow |
| `delonix-os-tools` | `delonix-doctor`, `delonix-toolbox` | this changes most: every new tool is a line |
| `delonix-os` | meta-package | one place to add future pieces |

**What stays in the overlay, and why**: `/etc/skel` (read only when a user is
created — updating it later changes nothing for existing users) and the two files
owned by other packages, `/etc/default/grub` (from `grub`) and
`/etc/plymouth/plymouthd.conf` (from `plymouth`). Claiming those would make
pacman refuse the installation.

For those, the answer is **pacman hooks**: `95-delonix-plymouth.hook` and
`96-delonix-grub.hook` re-apply our choice after any `plymouth` or `grub`
upgrade. They are idempotent and respect anyone who changed the value on purpose
— they only correct an empty value or one still pointing at us. `apply-plymouth`
only rebuilds the initramfs when the theme is not inside it, to avoid paying that
cost on every upgrade.

What is left to close the loop is infrastructure, not design: publishing the
repository and signing it.

## 9. AUR compiled during the build, not installed afterwards

Chrome, Edge, MongoDB, `gcloud`, `claude-code`, Antigravity and `cloud-hypervisor`
only exist in the AUR, and the `pacman` used by `buildiso` does not know what the
AUR is. Rather than leaving installation for after first boot, the build compiles
them into a local `[delonix-aur]` repository.

manjaro-tools' `user-repos.conf` rejects `file://` repositories on purpose, so
the section is appended directly to the pacman configuration `buildiso` uses. If
a package fails to build, the ISO still ships without it — never an hour-long
build dying because of an upstream PKGBUILD.

## 10. One power manager, not three

The first build attempt died with `tuned and tlp are in conflict`. The root cause
was not the conflict itself — it was having **three** power managers on the list:
`tlp`, `power-profiles-daemon` and `tuned`. Even if pacman accepted them, they
would fight over the same CPU governor.

`tuned` stayed, because it covers both cases of this workstation: battery
profiles for laptop work, and `delonix-lab` (throughput, low latency, THP on
`madvise`) for running VMs. `tuned-ppd` completes it — it speaks the
power-profiles-daemon D-Bus API, so the Plasma power selector keeps working,
served by tuned underneath.

## 11. From "lean" to "complete" — and what that cost

The first version left language runtimes and cloud CLIs out, with a defensible
argument: +3.5 GB for tools half the people never use. The requirement changed
the criterion — the target became **open the laptop and build a real project**.

- **Languages installed *and* configured.** Installing `rust` is half the job;
  the other half is `~/.cargo/config.toml` with `mold` and `sccache`,
  `GOTOOLCHAIN=auto`, `uv` managing Pythons. Without that, everyone rediscovers
  the same configuration — and most never do.
- **`rust` from the repositories, not `rustup`.** rustup needs network to *have*
  a compiler; the package works on first boot, offline. Multiple toolchains are
  available on request. It is the choice that serves the 90%.
- **Databases installed, but stopped.** "Ships installed" cannot mean "eats RAM
  from boot": PostgreSQL + Redis + MongoDB asleep are ~600 MB. They are disabled,
  and `delonix-toolbox db start` handles startup — including the Postgres
  `initdb`, which otherwise produces an error nobody understands the first time.
- **Accepted cost**: the ISO goes from ~2.5 GB to ~5 GB and the installation from
  ~9 to ~18 GB. That is the price of not installing anything on day one, and it
  is written into the targets in [validation.md](validation.md).

What did not change is the underlying criterion: nothing ships without a
function. Office, PIM, games and file indexing stay out — and now desktop
animations too, which are GPU and memory spent on decoration.

## 12. Validate against Manjaro, not against Arch

For weeks `make check` confirmed packages against **archlinux.org**. That seemed
reasonable — Manjaro is derived from Arch. It took a 40-minute build to prove
they are not the same thing: `kind` and `intel-npu-driver` exist in Arch and
have not yet reached Manjaro **stable**, which is the branch we build against.
`buildiso` only said so at the end, with `target not found`.

The checker now goes to the right source: Manjaro's own databases (`core.db`,
`extra.db`, `multilib.db`) for the configured branch, with the AUR as a
fallback and a 12-hour local cache.

Two effects:

- **Correctness**: it validates against what `pacman` will actually find. It also
  reads the `%PROVIDES%` field, because that is how a request for `redis` is
  satisfied by `valkey` — without it, the checker rejected perfectly installable
  names.
- **Speed**: from ~12 minutes (one HTTP call per package) to **10 seconds**
  (three files, once a day). A check that takes twelve minutes does not get run
  before every change; one that takes ten seconds does.

The two missing packages moved to their AUR `-bin` variants (`kind-bin`,
`intel-npu-driver-bin`), with a comment saying to switch back to the repository
package once Manjaro syncs them.

## 13. Validation before the build

`verify-profile.sh` runs in seconds and catches what would otherwise only blow up
20 minutes into `buildiso`: a wrong package name, a referenced theme that does not
exist, a script with a syntax error, bloat that came back through the side door.
`--online` confirms every package against the Arch/AUR repositories **and**
cross-checks declared conflicts — which is exactly what the `tlp` vs `tuned`
failure taught us to automate.
